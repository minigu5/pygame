# 로비, 플레이어 형태, 연결 정리 설계

작성일: 2026-09-29
대상 이슈: #10, #12, #15

## 목표

방 코드를 외부에서 주고받지 않아도 방을 찾고 만들 수 있게 한다. 플레이어마다 서버가 관리하는 크기와 자세를 제공한다. 사용하지 않는 맵 연결 데이터와 오해를 부르는 연결 응답을 정리한다.

기존 `--room` 직접 접속은 유지한다. 서버는 물리와 방 목록의 권위자다. 클라이언트 예측은 서버가 정한 형태와 충돌 크기를 그대로 사용한다.

## 1. 로비와 방 목록 (#10)

### 방 레지스트리

새 `RegistryDO` Durable Object 하나가 공개 방 목록을 저장한다. Worker는 `GET /rooms`를 이 객체에 전달한다. 응답 항목은 방 코드, 플레이어 수, 정원, 단계(`waiting`, `hiding`, `seeking`, `result`)다. 방 코드는 표시 이름이자 접속 코드다.

각 `RoomDO`는 접속·퇴장·라운드 단계 변경 때 레지스트리에 상태를 보낸다. 활성 방은 30초마다 갱신한다. 레지스트리는 90초 이상 갱신되지 않은 항목을 목록 응답에서 제거한다. 마지막 플레이어가 나가면 즉시 삭제한다. Registry 저장소는 오래된 항목을 목록 요청 때 정리한다. 레지스트리 통신 실패는 게임 접속과 플레이를 막지 않는다.

레지스트리는 플레이어 좌표, ID, 색을 저장하거나 반환하지 않는다. 플레이어가 없는 방은 표시하지 않는다.

### 클라이언트 흐름

인자 없이 실행하면 로비를 연다. 로비는 방 목록, 새로고침, 선택 방 입장, 새 방 만들기를 제공한다. 새 방은 기존 방 URL 옵션(`hide`, `seek`, `result`)으로 설정하고, 검증된 임의 방 코드를 만든 뒤 WebSocket 첫 접속으로 생성한다. 방 이름과 코드는 같은 값으로 쓴다.

`--room CODE`가 있으면 로비를 건너뛰고 해당 방에 직접 접속한다. 기존 점검 스크립트와 링크 옵션은 계속 작동한다. 서버 주소에서 `ws`/`wss`를 `http`/`https`로 바꿔 방 목록을 읽는다. 새 라이브러리는 추가하지 않는다.

목록이 비었거나 HTTP 요청이 실패하면 이유와 다시 시도 동작을 표시한다. 방 목록은 생성 이후 WebSocket 연결이 성공해야 나타난다.

2026-10-05에 고친 점:

- 방은 두 명이 모여도 저절로 시작하지 않는다. 가장 오래 있던 사람이 방장이고, 방장이 `start`를 보내야 첫 판이 시작된다.
- 설정(방 이름, 최대 인원 2~8명, 단계 길이)은 로비가 아니라 대기실에서 방장이 `cfg`로 바꾼다. 서버는 바뀔 때마다 `r` 메시지로 방 상태를 모두에게 알린다. 방 이름은 코드와 별개의 표시 이름이고, 레지스트리 항목에도 실린다.
- 게임 도중에 나갈 수 있다. 헌터가 나가면 그 판은 카멜레온 승리로 끝나고, 한 명만 남으면 대기실로 돌아간다.
- 방 목록 요청에는 `User-Agent`를 붙인다. Cloudflare가 `Python-urllib` 기본값을 403(오류 1010)으로 막아, 목록이 늘 실패로 보였다.

### Worker 경로와 배포

`GET /rooms`는 레지스트리 목록을 반환한다. 기존 `GET /ws?room=CODE`는 유지한다. Wrangler에 `REGISTRY` 바인딩과 새 SQLite Durable Object migration을 추가한다. 방별 설정은 현재처럼 첫 접속 URL에서 읽는다.

## 2. 플레이어 자세와 크기 (#12)

### 상태 모델

플레이어 상태에 `pose`(`stand`, `crouch`, `lie`)와 `size`(`small`, `normal`, `large`)를 둔다. `shared/tuning.json`의 `shape_sizes`에 자세별 크기 표를 두고 서버와 클라이언트가 함께 읽는다. 기본 서기 크기는 기존 24×32px다. 자세별 기준 크기는 서기 24×32px, 웅크리기 24×20px, 눕기 36×12px다 (2026-09-29: 눕기를 36×16에서 36×12로 낮췄다. 낮은 가구 뒤에 숨는 용도라 낮을수록 좋고, 그린 실루엣도 그 높이면 충분했다). 크기 배율은 작은 0.5, 기본 1, 큰 1.5다. 최종 치수는 양의 정수 픽셀로 반올림한다.

헌터와 카멜레온 모두 형태를 바꿀 수 있다. 잡힌 플레이어와 관전자는 바꿀 수 없다. 자세는 `↓`/`↑` 키나 팔레트 위의 버튼으로 바꾼다. 숫자키 `1`~`4`는 붓이 쓰므로 크기 키는 다시 정한다. HUD에 조작법과 현재 선택을 표시한다.

2026-09-29 기준 클라이언트 쪽은 구현됐다: 사람 실루엣, 자세 셋, 자세마다 하나의 그림을 변환해 보여 주기 (`client/body_shape.py`). 다만 고정 모드에서만 바꿀 수 있고 고정을 풀면 차렷으로 돌아오며, 서버 권위·충돌 검사·스냅샷 전달·크기 배율은 남아 있다.

### 서버 권위와 충돌 처리

클라이언트는 `shape` 메시지로 자세와 크기를 요청한다. 서버는 허용된 enum만 받으며 현재 물리 틱에서 새 치수가 맵 충돌과 겹치면 요청을 거절한다. 적용할 때 지면에 있으면 발 위치를, 공중이면 몸 중심을 유지한다. 새 형태가 벽에 겹치면 상태와 위치를 바꾸지 않는다.

서버 물리는 플레이어별 치수를 충돌, 사다리 판정, 방 판정, 지목 판정에 사용한다. 스냅샷의 나와 다른 플레이어 데이터에 자세와 크기를 포함한다. 클라이언트 예측과 렌더링은 같은 프리셋을 사용한다. 예측 변경이 거절되면 다음 스냅샷이 형태와 위치를 보정한다.

새 라운드 시작 때 모든 플레이어를 기본 크기·서기 상태로 초기화한다. 페인트 색과 잡힘 규칙은 유지한다.

## 3. 정리 (#15)

### 미사용 `doors`

맵 연결 배열은 소비자가 없다. `tools/make_building_map.py` 출력과 `shared/map_01.json`에서 `doors`를 제거한다. 기술 설계서의 예시와 설명에서도 제거한다. 문 통과는 기존 충돌 맵의 빈 공간으로 계속 결정한다.

### `hello` 역할

`hello.role`은 접속 순간 항상 `spectator`라 제거한다. 메시지는 ID, 틱, 맵 이름만 전달한다. 실제 역할은 첫 스냅샷의 `me.rl`로 정한다. 클라이언트와 점검 도구는 `hello.role`에 의존하지 않는다.

### 연결 오류

WebSocket 거절 상태를 사용자 문구로 변환한다. HTTP 409는 방이 가득 참, HTTP 400은 잘못된 방 코드로 표시한다. 네트워크 연결 실패는 서버 주소와 네트워크 확인 안내를 표시한다. 원시 Python 예외 문자열은 게임 화면에 표시하지 않는다.

## 공통 제약과 완료 조건

- `--room` 직접 접속과 기존 WebSocket 게임 프로토콜은 유지한다.
- 레지스트리 데이터에 위치 정보나 플레이어 개인 정보를 넣지 않는다.
- 새 런타임 의존성을 추가하지 않는다.
- 클라이언트와 서버 물리 프리셋 정의는 동일한 값을 사용한다.
- #10: 로비에서 현재 방을 조회하고, 입장하거나 새 설정으로 방을 열 수 있다.
- #12: 세 크기와 세 자세가 화면·충돌·지목 범위에 함께 반영된다.
- #15: dead `doors` 필드가 생성되지 않고, `hello`가 역할을 주장하지 않으며, 연결 실패가 읽기 쉬운 문구를 보인다.

## 검토할 위험

- 형태 조합이 9개라 좁은 통로에서 큰 형태 변경이 거절될 수 있다. HUD에서 현재 형태를 보여 실패처럼 보이지 않게 한다.
- Registry Durable Object는 단일 목록 병목이다. 소규모 친구 방 검색 용도에 한정하며, 좌표와 실시간 플레이 메시지는 통과시키지 않는다.
- 메인 스레드에서 방 목록 요청이 멈추지 않도록 HTTP 조회는 백그라운드 작업으로 수행한다.
