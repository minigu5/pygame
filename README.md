# 메챠 카멜레온 2D

2D 횡스크롤 위장 숨바꼭질 게임. 카멜레온은 몸을 배경색으로 칠해 숨고, 헌터는 방을 뒤져 찾는다.

문서는 `docs/superpowers/specs/`에 있다.

- [기술 설계서](docs/superpowers/specs/2026-09-21-chameleon-design.md) — 서버 구조, 프로토콜, 물리, 배포
- [게임 기획 스펙](docs/superpowers/specs/2026-09-21-meccha-chameleon-2d-game-spec.md) — 맵, 시야, 칠하기, 라운드

## 구조

| 경로 | 내용 |
| --- | --- |
| `client/` | pygame-ce 클라이언트 (Python) |
| `server/` | Cloudflare Workers + Durable Objects 서버 (TypeScript) |
| `shared/` | 맵과 튜닝 값처럼 양쪽이 함께 읽는 데이터 |
| `tools/` | 맵 생성, 웹 빌드, 점검용 스크립트 |

## 준비

Python 3.13 이상과 Node.js 20 이상이 필요하다.

```sh
python3 -m venv .venv
.venv/bin/pip install -r client/requirements.txt
npm install --prefix server
```

## 실행

서버는 `wss://chameleon.omm.run`에 배포되어 있다. 클라이언트는 창 하나가 플레이어 한 명이다.

```sh
.venv/bin/python client/main.py
```

처음 화면은 로비다. 지금 열려 있는 방의 이름, 인원, 상태(대기 중 / 게임 중 / 가득 참)가 보이고 4초마다 새로 읽는다. 방을 골라 **입장**하거나(더블클릭, Enter) **새 방 만들기**(N)로 방을 연다. 게임 중인 방에 들어가면 그 판은 구경하고 다음 판부터 함께한다.

방에 들어가면 대기실이다. 방을 연 사람이 방장이고, 방장만 설정을 바꾸고 판을 시작할 수 있다. 방장이 나가면 가장 오래 있던 사람이 방장이 된다.

| 설정 | 기본 | 범위 |
| --- | --- | --- |
| 방 이름 | `방 xxxx` | 16자까지, 한글 가능 |
| 최대 인원 | 4명 | 2~8명, 지금 있는 사람 수보다 줄일 수 없음 |
| 숨는 시간 | 60초 | 5~180초 |
| 찾는 시간 | 120초 | 10~600초 |
| 결과 표시 | 5초 | 2~30초 |
| 배경 | 사무실 | 맵에 적힌 배경 가운데 하나 (`<` / `>`로 넘긴다). 첫 판의 배경이고, 다음 판부터는 서버가 직전과 다른 배경을 무작위로 고른다 |

두 명 이상 모인 뒤 방장이 **게임 시작**을 눌러야 라운드가 시작된다. 한 명이 헌터, 나머지가 카멜레온이고, 판이 끝나면 역할을 바꿔 다음 판으로 넘어간다. 설정은 대기실에서만 바꿀 수 있다.

게임 도중에도 Esc로 메뉴를 열어 **방 나가기**를 고르면 로비로 돌아온다. 남은 사람이 한 명이면 그 방은 대기실로 돌아가고, 헌터가 나가면 그 판은 카멜레온의 승리로 끝난 뒤 남은 사람끼리 다음 판을 한다. 접속이 거절되거나(방이 가득 참 등) 끊기면 이유와 함께 로비로 돌아온다.

방 코드를 알면 로비를 건너뛰고 바로 들어갈 수 있다. 없는 방이면 그 코드로 새로 열린다.

```sh
.venv/bin/python client/main.py --room test
```

| 단계 | 기본 길이 | 카멜레온 | 헌터 |
| --- | --- | --- | --- |
| 숨는 시간 | 60초 | 이동, 고정, 칠하기 | 화면이 가려지고 조작할 수 없음 |
| 찾는 시간 | 120초 | 이동, 고정 | 이동, 지목 |
| 결과 | 5초 | 결과 표시 | 결과 표시 |

시간이 다 갈 때까지 한 명이라도 숨어 있으면 카멜레온이 이기고, 전원이 잡히면 헌터가 이긴다. 헌터가 아무 데나 눌러 대지 못하도록 한 판에 틀릴 수 있는 지목은 3번뿐이고(`shared/tuning.json`의 `accuse_misses`), 세 번째로 빗나가면 그 자리에서 카멜레온의 승리로 끝난다. 남은 기회는 찾는 시간 동안 화면 위 띠에 모두에게 보인다.

방을 여는 사람은 주소로도 설정을 줄 수 있다 (`name`, `max`, `hide`, `seek`, `result`, `bg`). 범위는 대기실과 같고 `shared/tuning.json`의 `room_limits`에 있다. 빈 방에 처음 들어가는 사람이 방을 새로 여는 것으로 친다.

```sh
.venv/bin/python client/main.py --room "test&hide=20&seek=45"
```

로컬 서버로 개발할 때는 이렇게 한다.

```sh
npm run dev --prefix server                                   # http://127.0.0.1:8787
.venv/bin/python client/main.py --server ws://127.0.0.1:8787
```

## 브라우저에서 하기

같은 클라이언트를 [pygbag](https://pygame-web.github.io/)으로 묶어 서버가 함께 내보낸다. 설치 없이 브라우저로 서버 주소(`https://chameleon.omm.run`)를 열면 pygame 코드가 WebAssembly로 그대로 돈다. 처음 열 때 파이썬과 pygame을 받아 오느라 십여 초 걸린다.

```sh
.venv/bin/pip install pygbag
.venv/bin/python tools/build_web.py     # client/ 와 shared/ 를 묶어 server/public/ 에 놓는다
```

`server/public/`은 빌드 결과라 저장소에 넣지 않는다. 클라이언트나 `shared/`를 고쳤으면 배포하기 전에 다시 빌드한다. 로컬에서는 `npm run dev --prefix server` 뒤에 `http://127.0.0.1:8787`을 연다 (`localhost`로 열면 pygbag이 자기 개발 서버를 찾느라 멈춘다).

브라우저에는 스레드도 파이썬 소켓도 시스템 글꼴도 없어서 이 부분만 다르게 돈다.

- 화면마다 도는 루프는 코루틴이고 프레임마다 브라우저에 차례를 넘긴다 (`await asyncio.sleep(0)`). 데스크톱에서도 같은 코드가 돈다.
- 접속과 방 목록은 페이지의 WebSocket과 fetch가 맡고, 파이썬은 프레임마다 쌓인 것을 읽어 간다 (`client/web.py`). 서버 주소는 페이지를 내보낸 그 서버다.
- 글자는 함께 묶은 Noto Sans KR로 그린다 (`client/assets/fonts/`, 한자를 뺀 것, SIL Open Font License).
- 브라우저는 접속이 왜 거절됐는지 알려 주지 않아서 방이 가득 찼을 때와 서버에 닿지 못했을 때의 안내가 같다. 캔버스에서는 한글 조합이 되지 않아 방 이름은 영문과 숫자로만 고칠 수 있다. 탭이 가려져 있는 동안에는 게임이 멈춘다.

## 배포

```sh
.venv/bin/python tools/build_web.py
npx wrangler deploy --config server/wrangler.jsonc
```

방마다 `RoomDO` 하나가 게임을 돌리고, `RegistryDO` 하나가 로비에 보여 줄 방 목록(`GET /rooms`)을 맡는다. 서버와 클라이언트는 같은 프로토콜을 써야 하므로, 서버 코드를 고쳤으면 배포한 뒤에 그 클라이언트로 접속한다.

Durable Object에는 위치 힌트를 주지 않는다. 배치는 객체가 처음 만들어질 때 정해지므로, 방을 여는 사람 근처에 잡히게 두는 편이 지역을 찍는 것보다 낫다.

## 조작

| 키 | 카멜레온 | 헌터 |
| --- | --- | --- |
| ←/→, A/D | 이동 | 이동 |
| W | 점프 | 점프 |
| Space | 고정 모드 켜기/끄기 | - |
| W / A / S / D | 고정한 채 위 / 왼쪽 / 아래 / 오른쪽으로 천천히 옮기기 (고정 중에만) | - |
| E | 스포이드 모드 (고정 중에만) | - |
| 마우스 왼쪽 | HSB 슬라이더, 붓 고르기, 스포이드로 색 찍기 | 지목 (빗나가면 3초 쿨다운, 한 판에 3번 빗나가면 패배) |
| 마우스 휠 | 캐릭터 쪽으로 확대/축소 (고정 중에만, 풀면 원래대로) | - |
| 마우스 왼쪽 누른 채 이동 | 커서가 지나간 몸을 고른 색으로 칠함 (고정 중, 스포이드가 꺼져 있을 때) | - |
| 1 / 2 / 3 / 4 | 붓 굵기 가늘게 / 보통 / 굵게, 지우개 (고정 중에만) | - |
| ↓ / ↑ | 자세 낮추기 / 높이기: 차렷 → 웅크리기 → 눕기 (고정 중에만) | - |
| Ctrl+Z | 칠하기 되돌리기, 최대 30단계 (고정 중에만) | - |
| N | 소리 끄기/켜기 | 소리 끄기/켜기 |
| Esc | 메뉴: 계속하기 / 방 나가기 / 게임 종료 | 같음 |

로비에서는 ↑/↓로 방을 고르고 Enter로 입장, N으로 새 방, R로 새로고침, Esc로 종료한다.

글자 키는 한/영 상태와 상관없이 듣는다. 한글 상태에서 ㅡ가 찍히는 키는 M으로, ㅜ는 N으로 읽는다. 게임 화면에서는 입력기(IME)의 조합을 꺼 두고, 대기실에서 방 이름을 고칠 때만 켜서 한글을 입력한다 (`client/keys.py`).

화면의 글자는 모두 한글이 있는 글꼴 하나로 그린다 (`client/fonts.py`). 글꼴에 없는 글자는 빈 상자로 찍히므로, 다른 사람이 지은 방 이름에 그런 글자가 있으면 `?`로 바꿔 보여 준다.

걸을 때는 옆모습으로 바뀌어 팔다리를 앞뒤로 흔들며 가는 방향을 본다. 멈추면 다시 정면 차렷이다. 이 동작은 화면에서만 계산하고(내 몸은 예측한 속도로, 다른 플레이어는 위치 변화로) 서버와는 주고받지 않는다.

카멜레온은 고정 모드에서만 칠할 수 있다. 몸은 사람 실루엣이고, 그 위에 96×128 해상도의 그림을 부드러운 둥근 붓으로 칠한다. 고정한 뒤 휠로 캐릭터를 확대하고, 오른쪽 아래 팔레트에서 색과 붓을 고른 다음 게임 화면의 몸 위에서 마우스 왼쪽을 누른 채 움직여 칠한다. 버튼을 누른 순간부터 뗄 때까지가 한 획이고, Ctrl+Z 한 번이 한 획을 되돌린다. 물감이 묻는 동안에는 붓 쓸리는 소리가 나고, 붓을 멈추면 곧 잦아든다.

고정한 몸은 W/A/S/D로 옮겨 자리를 맞출 수 있다. 걷는 속도(초당 200px)보다 훨씬 느린 초당 60px, 곧 한 프레임에 1px씩 움직이고(`shared/tuning.json`의 `frozen_move_speed`), 중력을 받지 않으므로 놓은 자리에 그대로 떠 있는다. 벽과 바닥은 그대로 막힌다. 고정 중의 ↑/↓는 자세를 고르는 키라서 몸을 옮기지 않는다.

고정 중에는 자세도 바꿀 수 있다. 차렷(24×32), 웅크리기(24×20), 눕기(36×12) 세 가지이고, ↓/↑ 키나 팔레트 위의 버튼으로 고른다. 그림은 자세와 상관없이 하나라서 차렷 자세에서 머리에 칠한 색은 웅크려도 머리에 남는다. 다만 누우면 그림이 길게 눌리므로, 숨을 자세로 바꾼 뒤에 칠하는 편이 정확하다. 고정을 풀면 차렷으로 돌아온다. 칠한 그림은 그 판에서만 쓰고, 다음 판이 시작되면(또는 대기실로 돌아가면) 맨몸 색으로 지워진다. 칠한 그림과 자세는 같은 방에 있는 다른 플레이어에게 그대로 보인다. 그림은 획이 끝날 때마다 서버를 거쳐 전해지고, 같은 방에 들어온 사람에게만 간다 (그림은 어느 방에 숨을지를 말해 주기 때문이다). 다만 자세는 보이는 모습일 뿐이라 서버의 충돌 상자와 지목 범위는 24×32 그대로다. 화면은 지금 있는 방을 중심에 두고, 방 바깥은 회색으로 죽여 그린다.

맵(`shared/map_01.json`)은 사방이 막힌 방 하나다. 그 방에 무엇을 깔지는 방장이 대기실의 **배경** 설정으로 고르고, 서버가 모두에게 알려 같은 그림을 본다. 고를 수 있는 배경은 `tools/make_building_map.py`의 `BACKGROUNDS`에 id와 이름으로 적고 맵을 다시 만든다. 그림은 `client/assets/rooms/`에 배경 id와 같은 이름(`sea.jpg`처럼 png, jpg, webp)으로 넣는다. 그림이 없는 배경은 맵의 벽지 색으로 보인다. 비율이 방과 다르면 가운데를 기준으로 넘치는 쪽을 잘라 맞춘다. 모두가 한 방에 있으므로, 숨는 시간 동안 서버는 헌터에게 다른 플레이어를 보내지 않는다. 스포이드도 그림의 색을 찍는다.

## 점검

서버가 떠 있는 상태에서 접속과 ping 왕복을 확인한다.

```sh
.venv/bin/python tools/smoke_ws.py            # 접속, 물리, 도색, 지목
.venv/bin/python tools/check_lobby.py           # 방 목록, 대기실 설정, 방장의 시작, 도중에 나가기
.venv/bin/python tools/check_rounds.py          # 숨기, 찾기, 결과, 역할 교대
.venv/bin/python tools/check_paint_sync.py      # 칠한 그림과 자세가 술래에게 그대로 보이는지
.venv/bin/python tools/check_fonts.py           # 화면에 나오는 글자가 모두 글꼴에 있는지 (서버 없이)
.venv/bin/python tools/check_physics_parity.py  # 클라 예측이 서버와 일치하는지
.venv/bin/python tools/check_body_shapes.py     # 실루엣, 자세별 그림 변환, 붓과 되돌리기 (서버 없이)
.venv/bin/python tools/check_client_sync.py     # 실제 클라이언트를 키 입력 대본으로 돌려 고정·카메라·입력 지연 확인
```

## 작업 규칙

기능마다 `feat/<단계>-<내용>` 브랜치를 만들고 PR로 `main`에 합친다. 자세한 내용은 기획 스펙 10절에 있다.
